# 第十二册：知识库产品完整链路

本册从“知识库”一级菜单出发，串联列表、创建、配置、文档、测试、图谱、知识编译和删除。文档解析细节参见[第二册](./02_文档摄取与深度解析.md)，检索算法参见[第三册](./03_检索问答与引用.md)。

## 1. 页面与路由

前端路由集中在 `web/src/routes.tsx`：

| 页面 | 前端目录 | 作用 |
|---|---|---|
| 知识库列表 | `web/src/pages/datasets/` | 查询、筛选、创建、重命名、删除 |
| 文档列表 | `web/src/pages/dataset/` | 上传、解析、停止、删除、预览 |
| 检索测试 | `web/src/pages/dataset/testing/` | 调整阈值、权重、候选数并查看 Chunk |
| Overview | `web/src/pages/dataset/dataset-overview/` | 数据量、摄取情况和结构概览 |
| Settings | `web/src/pages/dataset/setting/` | Embedding、权限、解析器、Dataflow、标签 |
| Knowledge Graph | `web/src/pages/dataset/knowledge-graph/` | 查看和删除 GraphRAG 图 |
| Compilation | `web/src/pages/dataset/compilation/` | Wiki、Skill、导航和结构产物 |

前端请求主要位于 `web/src/services/knowledge-service.ts`、`web/src/hooks/use-knowledge-request.ts` 和文档上传相关 Hook。

## 2. 数据模型边界

```text
Tenant
  └─ Knowledgebase
       ├─ Document ─< Task
       ├─ Connector2Kb
       ├─ GraphRAG/RAPTOR/Wiki 等 task_id
       └─ Doc Store Chunk(kb_id)

File ─< File2Document >─ Document
```

`Knowledgebase` 保存知识库级默认值：

- `tenant_id`、`created_by`、`permission`；
- `embd_id/tenant_embd_id`；
- `parser_id/pipeline_id/parser_config`；
- `similarity_threshold/vector_similarity_weight`；
- `doc_num/chunk_num/token_num`；
- GraphRAG、RAPTOR、Wiki、Skill 和结构任务标识。

`Document` 会复制创建当时的 parser/pipeline 配置。修改知识库默认设置后，已有 Document 是否同步变化要看具体更新接口，不能仅凭知识库字段推断。

## 4. 创建知识库

```text
dataset-creating-dialog
  → knowledge-service
  → POST /api/v1/datasets
  → create_dataset
  → 校验租户、名称、parser/pipeline 和模型
  → KnowledgebaseService.create_with_name
  → MySQL knowledgebase
  → 返回 dataset_id
```

创建时应关注：

- 同一租户内名称去重；
- `parser_id` 和 `pipeline_id` 的互斥/配合关系；
- Embedding 模型是否已配置；
- `permission=me|team`；
- parser config 是否来自默认值、模板或页面表单。

创建知识库不会立刻创建 ES Chunk。索引通常在首个解析 Task 的 `_init_kb()` 中按 tenant、向量维度和 parser 创建/检查。

## 5. 列表与访问范围

列表接口支持关键字、分页、排序和 owner 过滤。可见性结合：

```text
Knowledgebase.tenant_id
Knowledgebase.permission
UserTenant(user_id, tenant_id, role)
```

页面上的“Owner”不只是展示字段，它决定团队知识库过滤和后续修改权限。读取团队共享知识库和修改/删除他人知识库通常是不同权限等级。

## 6. Settings 的配置分组

### 模型与检索

- Embedding 模型；
- 默认相似度阈值；
- 向量权重；
- PageRank/标签等增强配置。

切换 Embedding 模型涉及向量空间变化。`/embedding/check` 可做兼容性检查，但已有 Chunk 最终仍需重新 Embedding/索引才能完整切换。

### 解析方式

- `parser_id`：内置解析策略；
- `parser_config`：chunk token、overlap、delimiter、layout、metadata 等；
- `pipeline_id`：改走 Dataflow Canvas。

### 数据源

知识库可绑定 Connector。同步过程产生 `SyncLogs`，下载/转换完成后继续复用 Document 和摄取链路。

### 权限

`me` 表示所有者空间，`team` 允许团队成员访问。路由仍需验证调用者确实属于该 tenant。

## 7. 文档列表

知识库详情页把 Document 作为主要资源：

```text
上传 → Document.run=0
解析 → Document.run=1 + Task
完成 → run=3 + chunk/token 统计
失败 → run=4 + progress_msg
停止 → run=2
```

常见操作：

- 本地上传；
- 从文件管理链接；
- 修改 parser/config/metadata；
- 批量解析或停止；
- 预览原文和 Chunk；
- 删除文档及索引结果。

## 8. 检索测试页

Testing 页面直接调用 dataset search，不经过 Chat 模型：

```text
问题 + 参数
  → /datasets/<id>/search
  → search/search_datasets
  → Dealer.retrieval
  → 返回 chunks、分数、doc_aggs
```

适合用来判断问题出在“召回”还是“回答生成”。如果这里已经没有正确 Chunk，修改 Chat Prompt 通常无效。

## 9. 标签和元数据

知识库支持：

- 标签聚合和重命名；
- 文档 metadata 配置；
- metadata summary；
- flattened metadata；
- 检索前 metadata filter。

元数据过滤先得到允许的 `doc_id` 范围，再作为 Doc Store filter，不属于相关性分数本身。

## 10. GraphRAG、RAPTOR 与 Compilation

这些能力不是创建知识库后自动全部存在：

- GraphRAG 需要单独构建实体关系；
- RAPTOR 需要构建层级摘要；
- Wiki/Skill/Navigation/Structure 使用特殊 Task 和 `compile_kwd`；
- Knowledgebase 保存相应 task_id 和完成时间。

具体参见[第十一册](./11_高级RAG与数据流水线.md)。

## 11. 删除知识库

删除不能只删 `knowledgebase` 行。完整清理可能涉及：

- 运行中的 Task 与特殊任务；
- Document、File2Document 关系；
- MinIO bucket/对象；
- tenant 索引中该 `kb_id` 的 Chunk；
- metadata index；
- Connector 和 SyncLogs；
- GraphRAG/RAPTOR/Compilation 派生记录；
- Chat/Search 对该知识库的引用。

代码应从 Knowledgebase Service/联合删除服务进入，禁止直接执行单表 SQL。

## 12. 调试入口

```bash
rg '@manager.route\("/datasets' api/apps/restful_apis
rg 'create_dataset|delete_dataset|update_dataset' api/apps/services
rg 'useCreateDataset|listDataset|useFetchDataset' web/src
rg 'pipeline_id|parser_config|embd_id' api/db/services/knowledgebase_service.py
```

建议关联：`tenant_id → kb_id → doc_id → task_id → chunk_id`。
