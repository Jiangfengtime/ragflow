# 第十四册：搜索应用完整链路

“搜索”一级菜单是一个可保存、可分享、可生成摘要的检索应用。它不同于知识库 Testing 页面：Testing 主要观察 Chunk，Search App 还保存产品配置并可流式生成结果。

## 1. 前端结构

```text
web/src/pages/next-search/
  ├─ index.tsx                 Search 应用入口
  ├─ search-home.tsx           初始页
  ├─ searching.tsx             查询运行页
  ├─ search-view.tsx           结果展示
  ├─ search-setting.tsx        配置
  ├─ retrieval-documents/      召回文档/Chunk
  ├─ mindmap-sheet.tsx         思维导图
  ├─ embed-app-modal.tsx       嵌入/分享
  └─ share/                    分享页
```

请求封装在 `web/src/services/search-service.ts`。

## 2. 数据模型

`Search` 表主要字段：

| 字段 | 含义 |
|---|---|
| `id` | Search App ID |
| `tenant_id/created_by` | 所有者 |
| `name/description/avatar` | 展示信息 |
| `search_config` | 数据集、检索、摘要和页面功能配置 |
| `status` | 有效状态 |

`search_config` 是 JSON，包含 `kb_ids/doc_ids`、阈值、向量权重、Rerank、top_k、Chat 模型参数、跨语言、关键词、Web Search、Related Search 和 Mindmap 等。

## 3. CRUD 接口

```text
POST   /searches
GET    /searches
GET    /searches/<search_id>
PUT    /searches/<search_id>
DELETE /searches/<search_id>
```

创建只要求名称，完整 `search_config` 可在设置页更新。更新接口会将传入 config 与当前 config 浅合并，嵌套字段是否完整保留取决于前端提交结构。

删除当前调用 `SearchService.delete_by_id`，与 Chat 的软删除实现不同，阅读代码时不要假设所有应用都只改 `status`。

## 4. Completion 接口

```text
POST /searches/<search_id>/completion
POST /searches/<search_id>/completions
```

两个 URL 指向同一实现。请求至少包含 `question`。

```text
search_id
  → SearchService.get_detail
  → 读取 search_config
  → 决定 kb_ids
  → 验证每个知识库权限
  → async_ask(question, kb_ids, tenant, search_config, search_id)
  → SSE 返回答案、引用与最终标记
```

## 5. 与 `search_datasets` 的关系

Search App 本身不实现另一套检索器：

```text
Search.search_config
  → async_ask / dataset search service
  → settings.retriever.retrieval
  → Dealer.search
  → Doc Store
```

`search_id` 会被传入底层，用来加载已保存配置并关联日志。BM25、KNN、融合和 Rerank 仍按[第三册](./03_检索问答与引用.md)执行。

## 6. 配置分组

### 检索范围

- `kb_ids`；
- `doc_ids`；
- metadata filter；
- 是否包含知识编译产物。

### 相关性

- `similarity_threshold`；
- `vector_similarity_weight`；
- `top_k`；
- `rerank_id`；
- `rerank_candidates_count`。

### 查询增强

- `cross_languages`；
- `keyword`；
- `use_kg`；
- `web_search`；
- `related_search`。

### 展示/生成

- `summary`；
- Chat 模型和生成参数；
- `highlight`；
- `query_mindmap`。

## 7. Search 与 Chat 的区别

| 维度 | Search App | Chat App |
|---|---|---|
| 核心模型 | `Search` | `Dialog` |
| 主要交互 | 单次查询/结果页 | 多轮 Conversation |
| 历史 | 不以 Conversation 为核心 | 保存 Session 和消息 |
| 配置重点 | 检索、摘要、Web/相关搜索 | Prompt、LLM、多轮、引用 |
| 共同底座 | Dealer、知识库、Embedding、Rerank | Dealer、知识库、Embedding、Rerank |

## 8. 权限与分享

Search 详情会在当前用户所属租户中查找；修改和删除要求所有权。执行 completion 时还会重新验证 `kb_ids`，避免分享或配置残留导致越权。

分享页面位于 `next-search/share/`，需要继续区分内部登录接口和公开接口使用的认证 Token。

## 9. 调试入口

```text
next-search hooks
  → search-service
  → search_api.completion
  → async_ask
  → search_datasets
  → Dealer.retrieval
  → SSE
```

关键 ID：`search_id → kb_ids → doc_ids → chunk_ids`。

日志：

```text
知识库检索已开始 search_id=...
检索候选集已获取 trace_id=...
检索候选集排序完成 trace_id=...
知识库检索完成 search_id=...
```

## 10. 常见故障

| 现象 | 检查 |
|---|---|
| 保存后配置丢失 | PUT body、浅合并、嵌套字段 |
| Search 无数据 | kb_ids、权限、ES Chunk |
| Testing 有结果，Search 无结果 | Search 保存阈值、doc_ids、metadata filter |
| SSE 有答案无来源 | summary/引用配置、检索结果 |
| 分享页失败 | 分享 Token、Search 状态、知识库权限 |
