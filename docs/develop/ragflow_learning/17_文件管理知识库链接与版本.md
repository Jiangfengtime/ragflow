# 第十七册：文件管理、知识库链接与版本

文件管理维护工作空间目录树和原始对象；知识库维护 Document 和检索索引。两者通过 `File2Document` 显式关联。文件管理列表与知识库文档列表的分流图见[第十九册](./19_知识库文档核心流程图.md)。

## 1. 前端入口

```text
web/src/pages/files/
  ├─ index.tsx                 列表与批量操作
  ├─ files-table.tsx           表格
  ├─ create-folder-dialog/     新建目录
  ├─ use-upload-file.ts        上传
  ├─ use-move-file.ts          移动/重命名
  ├─ link-to-dataset-dialog.tsx 链接知识库
  ├─ file-breadcrumb.tsx       面包屑
  └─ use-delete-file.ts        删除
```

请求封装：`web/src/services/file-manager-service.ts`。

## 2. `File` 与 `Document`

| 对象 | 作用 |
|---|---|
| `File` | 工作空间树节点，既可以是目录也可以是文件 |
| `Document` | 某知识库中的可解析文档 |
| `File2Document` | 一个 File 与一个或多个 Document 的关系 |

同一 File 可链接多个知识库，每个知识库创建独立 Document，因此：

```text
1 File
  ├─ Document(kb=A)
  └─ Document(kb=B)
```

两个 Document 可以使用不同 parser/config，生成各自 Chunk。

## 3. `File` 字段

| 字段 | 说明 |
|---|---|
| `id` | 节点 ID |
| `parent_id` | 父目录 ID |
| `tenant_id/created_by` | 所有者 |
| `name` | 页面名称，可重命名 |
| `location` | 对象存储 key |
| `size` | 字节数 |
| `type` | pdf/doc/visual/folder/virtual 等 |
| `source_type` | local、knowledgebase、skill_space 等来源 |

目录也是 File 行，`type=folder`。根目录通常使用自关联约定。

## 4. REST 接口

```text
POST   /files                   上传文件或创建目录
GET    /files                   列出目录
DELETE /files                   批量/递归删除
POST   /files/move              移动和重命名
GET    /files/<file_id>         下载
GET    /files/<file_id>/parent
GET    /files/<file_id>/ancestors
POST   /files/link-to-datasets
```

版本接口：

```text
POST/GET /workspaces/<id>/commits
GET      /workspaces/<id>/changes
GET      /workspace-files/<file_id>/versions
```

## 5. 上传文件

```text
FileUploadDialog
  → multipart POST /files
  → add_tenant_id_to_kwargs
  → file_api_service.upload_file
  → 确定 root/parent folder
  → 根据相对路径递归创建文件夹
  → 计算 FileType
  → MinIO.put(parent_folder.id, location, blob)
  → MySQL File.insert
```

文件管理对象的 bucket 通常是父目录 ID；知识库上传对象的 bucket 通常是 `kb_id`。不要把两条存储地址规则混淆。

## 6. 文件名与对象 key

`name` 是用户看到的名称，`location` 是对象 key。上传时两者可能初始相同，但重名处理和后续重命名会使它们不同。

纯重命名更新 File 和关联 Document 的 `name`，不要求移动对象，因为下载根据 `parent_id + location` 获取，而不是根据当前 `name` 猜对象 key。该路径不重新解析文档，也不在此刷新已有 Chunk 的标题字段。

## 7. 目录列表与面包屑

本节是顶部「文件管理」的目录列表。知识库文档列表走另一套接口，参见[第十二册](./12_知识库产品完整链路.md#7-文档列表)。

查询入口：

```text
useFetchFileList
  → GET /api/v1/files
  → file_api.list_files
  → file_api_service.list_files
  → FileService.get_by_pf_id
  → 返回 files / total / parent_folder
```

支持：

- `parent_id`；
- `keywords`；
- `page/page_size`；
- `orderby/desc`。

没有 `parent_id` 时获取租户根目录，并初始化知识库文档/Skills 等目录。普通列表查询当前目录的直接子节点；带 `keywords` 时搜索整棵子树。目录结果补充大小和子目录标志，文件结果通过 `File2Document` 补充已链接知识库 `kbs_info`。这里不检索 Chunk，也不调用大模型。`parent` 和 `ancestors` 接口用于面包屑。

## 8. 新建目录和虚拟文件

JSON `POST /files` 进入 `create_folder()`：

- 名称不能包含 `/`；
- 同父目录不能重名；
- parent 必须存在；
- type 为 folder 时创建真实目录节点，否则可创建 virtual 节点；
- 目录本身没有 MinIO blob。

## 9. 移动与重命名

`POST /files/move` 遵循类似 Linux `mv` 的组合语义：

| 参数 | 行为 |
|---|---|
| 只有 `dest_file_id` | 移动到新目录 |
| 只有 `new_name` | 原目录重命名 |
| 两者都有 | 移动并重命名 |

重命名只允许一个源文件；移动多个文件时要检查：

- 目标必须是目录；
- 不能移动到自身或子目录形成环；
- 目标目录重名；
- tenant/team 权限；
- 对象是否需要跨 bucket 迁移。

## 10. 链接到知识库

```text
POST /files/link-to-datasets?mode=add|replace
body: file_ids + kb_ids
```

链路：

```text
校验所有 File 和 Knowledgebase
  → 文件夹展开为叶子文件
  → 校验团队权限
  → add: 保留旧链接，跳过已存在 kb
     replace: 删除旧 Document 和关系
  → 为每个 File × KB 创建 Document
  → 复制 kb.parser_id/pipeline_id/parser_config
  → File2Document.insert
```

当前入口先检查权限，再把 `_convert_files()` 放入线程池后台执行，立即返回 `data=true`；这表示转换已调度，不能证明 Document 全部已创建。转换不会自动解析；完成后仍需调用 ingest/parse。前端若紧接着刷新知识库，可能暂时看到旧列表。

Document 的 `location` 可复用 File 的对象 key，`File2DocumentService.get_storage_address` 负责解析真实 bucket/key。

## 11. `add` 与 `replace`

- `add`：把文件追加链接到新知识库，保留已有 Document；
- `replace`：先删除旧 Document、Chunk 和关系，再按目标知识库重新创建。

请求没有 `mode` 时默认 **replace**；前端若想追加关联必须明确传 `mode=add`。replace 会删除该 File 的全部旧 Document（包括不在本次 `kb_ids` 中的旧关联），可能触发大量 Doc Store 清理；后续新 Document 的重新解析仍需单独请求，不是简单更新关联表，也没有跨存储原子事务。

## 12. 下载

```text
GET /files/<file_id>
  → 校验 tenant/team 权限
  → STORAGE_IMPL.get(file.parent_id, file.location)
  → 为空时通过 File2Document 回退解析地址
  → 安全 Content-Type/Disposition Header
```

两种来源的对象地址不同，下载实现因此先尝试 File 地址，再通过 File2Document 定位知识库对象。

## 13. 删除文件

`DELETE /api/v1/files` 接收 `file.id` 列表；知识库文档删除接收 `document.id`，见[第十二册](./12_知识库产品完整链路.md#72-删除知识库文档)。

普通单文件删除：

```text
file_api.delete
  → file_api_service.delete_files
  → 校验文件与团队权限
  → _delete_single_file
  → 删除原文件对象
  → 清理关联的 Document / File2Document
  → 删除 File 行
```

关联的 Document 由 `DocumentService.remove_document` 清理，其 Chunk 也随之删除。目录删除由 `_delete_folder_recursive` 递归处理子节点，并尝试删除目录对应的对象存储 bucket。知识库来源的 File 和 Skill Space 根节点不会从普通 `/files` 删除入口处理；Skills 子目录还可能先删除 Go 后端的 Skill 索引。

删除跨多个存储，可能部分成功。响应中的 `success_count/errors` 比 HTTP 状态更能说明实际结果。

## 14. 知识库虚拟目录

根目录列表会初始化知识库文档和 Skills 相关入口。`source_type=knowledgebase` 等节点可能禁止普通复选/移动操作，因为它们是业务视图，不完全等价于用户上传目录。

## 15. Commit 与版本历史

`FileCommit` + `FileCommitItem` 同时承载：

- 工作空间文件树提交；
- Artifact/Wiki 页面编辑版本。

工作空间 Commit 保存：

- parent commit；
- message、author；
- tree snapshot；
- 文件 add/modify/delete/rename；
- old/new hash、location 和 name。

相关接口支持列表、详情、文件清单、两个 Commit diff、未提交变更、树快照和历史文件内容。

当前路由已挂载 datasets 和 workspaces；memories/skills 的 resolver 注释说明尚未挂载，不能仅因通用函数存在就认为所有实体都支持 Commit。

`/datasets/<id>/commits` 的 resolver 当前直接使用 `kb_id`，主要承载 Artifact 页面编辑历史；`/workspaces/<id>/commits` 以目录 ID 承载文件树提交。路由工厂可生成通用方法，不表示每次上传、重命名或解析都自动创建 Commit。当前 `file_commit_api.py` 多数处理器只有 `login_required` 和 ID 归属匹配，没有复用文件列表的 `check_file_team_permission`；审查权限时应按具体入口检查，不能把普通 File 接口的授权结论套用于版本接口。

## 16. 权限边界

文件权限以 tenant、团队关系和特殊 source type 综合判断。路由使用 `add_tenant_id_to_kwargs`，客户端无法通过 body 自由指定 tenant。

链接知识库时必须同时具备：

- File 访问权限；
- 每个 Knowledgebase 访问权限。

## 17. 调试断点

上传：

```text
file_api.create_or_upload
  → file_api_service.upload_file
  → STORAGE_IMPL.put
  → FileService.insert
```

链接：

```text
file2document_api.convert
  → _convert_files
  → DocumentService.insert
  → File2DocumentService.insert
```

删除：

```text
file_api.delete
  → delete_files
  → _delete_single_file/_delete_folder_recursive
  → DocumentService.remove_document
```

## 18. 常见故障

| 现象 | 检查 |
|---|---|
| 列表有文件，下载为空 | parent_id/location、MinIO、fallback |
| 重命名后对象名没变 | 正常：name 与 location 分离 |
| 链接后知识库未解析 | 是否触发 ingest |
| 删除文件后知识库仍有 Chunk | remove_document、ES 清理 |
| 移动目录失败 | 环、重名、目标权限、bucket 迁移 |
| 批量删除部分成功 | 响应 data.errors |

## 19. 本册检查点

- 能区分 File、Document 和 MinIO 对象。
- 能解释一个 File 为什么对应多个 Document。
- 能说明重命名为什么不一定改 object key。
- 能解释 add/replace 链接模式。
- 能列出递归删除涉及的关系、对象和索引。
- 能区分工作空间 Commit 与 Artifact Commit。
