# 第十三册：聊天应用、会话与消息链路

“聊天”一级菜单管理的是可配置 RAG 应用，不只是一次模型请求。核心对象是 `Dialog`、`Conversation` 和知识库检索链路。

## 1. 三个对象不要混淆

| 对象 | 表 | 生命周期 |
|---|---|---|
| Chat/Dialog | `dialog` | 一个聊天应用的长期配置 |
| Session/Conversation | `conversation` | 用户在该应用下的一次会话 |
| Message | `Conversation.message` JSON | 会话中的 user/assistant 消息 |

公开 API/Agent 还会使用 `API4Conversation`，它与页面 Chat 的 `Conversation` 不是完全相同的表。

## 2. 前端入口

```text
web/src/pages/next-chats/
  ├─ index.tsx                 聊天应用列表
  ├─ hooks/use-create-chat.ts  创建
  ├─ chat/                     对话页面
  ├─ chat/app-settings/        模型、知识库、Prompt 等配置
  ├─ chat-stream/              SSE 状态
  └─ share/                    分享页
```

请求封装在 `web/src/services/next-chat-service.ts`。发送消息的主要 Hook 是 `use-send-chat-message.ts`。

## 3. Chat CRUD

```text
POST   /chats
GET    /chats
GET    /chats/<chat_id>
PUT    /chats/<chat_id>
PATCH  /chats/<chat_id>
DELETE /chats/<chat_id>
DELETE /chats
```

创建流程：

```text
创建对话框
  → POST /chats
  → 禁止客户端指定 tenant_id
  → 校验名称和 dataset_ids
  → 解析 Chat/Rerank 模型 ID
  → 合并 prompt 默认值
  → 写 Dialog
  → 返回标准化 Chat DTO
```

`PUT` 更接近完整配置更新，`PATCH` 会对 `llm_setting`、`prompt_config` 做局部合并。删除 Chat 是把 `status` 设为无效，属于软删除。

## 4. `Dialog` 关键配置

| 字段 | 作用 |
|---|---|
| `kb_ids` | 绑定知识库 |
| `llm_id/tenant_llm_id` | Chat 模型 |
| `rerank_id/tenant_rerank_id` | 可选重排模型 |
| `llm_setting` | temperature、top_p、max_tokens 等 |
| `prompt_config` | system、prologue、变量、empty_response |
| `similarity_threshold` | 召回阈值 |
| `vector_similarity_weight` | 文本/向量融合权重 |
| `top_n` | 最终上下文数量 |
| `rerank_candidates_count` | 重排候选窗口 |
| `top_k` | KNN 候选参数 |
| `do_refer` | 是否生成引用 |
| `meta_data_filter` | 元数据过滤 |

应用设置页保存的是这些字段，真正发送消息时再读取，构造 `Dialog` 运行上下文。

## 5. Session CRUD

```text
POST   /chats/<chat_id>/sessions
GET    /chats/<chat_id>/sessions
GET    /chats/<chat_id>/sessions/<session_id>
PATCH  /chats/<chat_id>/sessions/<session_id>
DELETE /chats/<chat_id>/sessions
```

创建 Session 时：

1. 验证 Chat 归属；
2. 生成 `Conversation.id`；
3. 把 Chat 的 `prompt_config.prologue` 写成第一条 assistant 消息；
4. 初始化 `reference=[]`；
5. 保存 `user_id`。

Session 更新接口只允许安全字段，例如名称；不允许通过普通 PATCH 任意覆盖 messages/reference。

## 6. 消息和引用的配对

`Conversation.message` 保存消息数组，`Conversation.reference` 保存每轮回答的检索引用。删除一轮消息时，代码同时删除对应 user/assistant 消息和 reference 项。

这意味着：

- message/reference 顺序必须一致；
- 手工修改 JSON 很容易破坏引用对应关系；
- 引用 Chunk 已从 ES 删除时，历史引用仍可能需要降级展示。

## 7. Completion 入口

```text
POST /chat/completions
```

主要请求字段：

| 字段 | 说明 |
|---|---|
| `chat_id` | 使用哪一个 Dialog 配置 |
| `session_id`/`conversation_id` | 继续已有会话；没有则创建 |
| `messages` 或 `question` | 输入消息 |
| `stream` | 是否 SSE |
| `pass_all_history_messages` | 是否以请求历史覆盖运行历史 |
| `store_history_messages` | 是否持久化历史 |
| `llm_id` | 可选临时覆盖模型 |

当不保存历史时，必须由调用者传递完整历史，否则模型没有上下文。

## 8. 一次发送消息

```text
前端 use-send-chat-message
  → POST /chat/completions
  → 验证 Chat/Session
  → 追加 user message
  → rag_agent(Dialog, history)
       ├─ 问题改写
       ├─ Dealer.retrieval
       ├─ 可选 GraphRAG/Web Search
       ├─ kb_prompt
       ├─ Chat LLM
       └─ citation
  → SSE 增量事件
  → 追加 assistant message/reference
  → 前端更新流式状态
```

检索和 Prompt 细节参见[第三册](./03_检索问答与引用.md)。

## 9. SSE 事件

流式接口使用 `text/event-stream`。客户端需要处理：

- 普通 answer delta；
- thinking 开始/结束事件；
- 引用和最终 answer；
- 错误事件；
- 流结束标记。

前端 `chat-stream/run-stream.ts` 和相关 Store 将网络事件转换为页面状态。SSE 连接断开不一定意味着服务端没有保存历史，应重新获取 Session 核对。

## 10. 反馈、删除和附件

Chat API 还包括：

- 删除单轮消息；
- 点赞/点踩和 feedback；
- TTS；
- ASR；
- 思维导图；
- 推荐问题；
- 会话附件上传。

删除 Session 时会尝试清理该会话上传到对象存储的附件。

## 11. 分享与公开调用

页面分享、Widget、OpenAI 兼容 API 和内部 Chat 页面可能使用不同路由/认证，但最终会加载相同 Chat 配置或对应的公开会话对象。

检查分享问题时要区分：

- 登录用户是否有 Chat 权限；
- 分享 Token/API Token 是否有效；
- `dialog_id` 是否绑定正确；
- 是否写 `Conversation` 还是 `API4Conversation`。

## 12. 权限

读取 Chat 时会遍历当前用户所属租户；修改和删除通常要求所有权。绑定 `kb_ids` 时还要逐个验证知识库可访问性，不能利用一个可访问 Chat 越权查询不可访问知识库。

## 13. 调试断点

```text
chat_api.session_completion
  → rag_agent
  → DialogService / Dealer.retrieval
  → kb_prompt
  → LLMBundle.async_chat
  → citation
  → ConversationService.update
```

关联字段：`chat_id → session_id → message_id → kb_id → chunk_id`。

## 14. 常见故障

| 现象 | 优先检查 |
|---|---|
| Chat 创建失败 | 默认模型、名称、dataset_ids |
| Session 不属于 Chat | dialog_id 与 chat_id |
| 有历史但模型不记得 | pass/store history 组合、token 截断 |
| 回答无引用 | do_refer、检索结果、citation |
| SSE 中途断开 | API traceback、代理缓冲、模型连接 |
| 删除后列表仍出现 | status 过滤和缓存失效 |

## 15. 本册检查点

- 能区分 Dialog、Conversation 和 API4Conversation。
- 能解释 Chat 配置如何影响检索与模型。
- 能跟踪一轮消息从前端、SSE 到历史持久化。
- 能说明 messages 与 reference 的对应关系。
- 能区分读取权限和修改所有权。
