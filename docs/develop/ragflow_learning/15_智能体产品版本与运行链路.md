# 第十五册：智能体产品、版本与运行链路

本册补充智能体作为产品的创建、编辑、发布、会话、调试、日志与 Webhook。Canvas/DSL 执行原理参见[第四册](./04_智能体与前端.md)。

## 1. 前端页面

```text
web/src/pages/agents/          列表、模板、创建、导入、标签
web/src/pages/agent/           Canvas 编辑器与运行
web/src/pages/agent/share/     分享运行
web/src/pages/agent/log-sheet/ 节点执行时间线
web/src/pages/agent/webhook-sheet/ Webhook 日志
```

主要服务在 `web/src/services/agent-service.ts`，路由在 `web/src/routes.tsx` 的 Agent、AgentShare、AgentLogPage 等节点。

## 2. 数据模型

### `UserCanvas`

| 字段 | 作用 |
|---|---|
| `id` | Agent/Canvas ID |
| `user_id` | 所有者/tenant |
| `title/description/avatar/tags` | 产品元数据 |
| `permission` | `me|team` |
| `release` | 是否发布 |
| `canvas_type` | 模板/类型 |
| `canvas_category` | `agent_canvas|dataflow_canvas` |
| `dsl` | 节点、边、变量和组件配置 |

### 相关模型

- `CanvasTemplate`：内置/可选模板；
- `UserCanvasVersion`：DSL 历史和发布版本；
- `API4Conversation`：Agent 会话；
- `MCPServer`：远程工具服务配置；
- Redis：短期运行日志和中间状态；
- `PipelineOperationLog`：Dataflow/摄取流水线日志。

## 4. 创建 Agent

```text
模板或空白 DSL
  → POST /agents
  → 注入 user_id/canvas_category
  → normalize_dsl
  → 校验 title 唯一
  → 保存 UserCanvas
  → 创建/更新 UserCanvasVersion
  → CanvasReplicaService.replace_for_set
  → 返回 Agent
```

`CanvasReplicaService` 维护 Redis 中的运行时可执行副本，key 为 `canvas:replica:<canvas_id>:<tenant_id>:<runtime_user_id>`，TTL 为 3 小时；丢失后可从数据库 DSL bootstrap。它与 MySQL `UserCanvas`、`UserCanvasVersion` 分开持久化。数据库保存成功但副本同步失败时，接口会明确返回“canvas saved, but replica sync failed”，这属于部分成功状态。

## 5. 编辑和保存

前端把画布状态转换为 DSL：

```text
React Flow nodes/edges/forms
  → use-build-dsl
  → PUT /agents/<id>
  → normalize_dsl
  → Canvas.validate_component_parameters
  → UserCanvas.update
  → UserCanvasVersion.save_or_replace_latest
  → 更新 runtime replica
```

保存失败应区分：

- 表单/组件参数错误；
- DSL 图结构错误；
- MySQL 保存失败；
- runtime replica 同步失败。

## 6. 版本与发布

`UserCanvasVersion` 保存：title、description、release、dsl。`save_or_replace_latest()` 按 **DSL 是否变化** 决定版本：内容相同通常更新最新行，内容变化创建新行；即使 DSL 相同，最新行已发布而此次保存未发布时也创建新版本。不能将其理解为“所有草稿编辑都覆盖最新未发布版本”。同 DSL 更新不会重写版本 title；清理仅保留最近 20 个未发布版本，已发布版本保留。

运行模式需要区分：

- 编辑/草稿调试：运行当前 runtime replica；
- 已发布分享：加载最新 released version；
- Session：创建时保存 version title，保证历史可追踪。

## 7. Canvas 运行

```text
POST /agents/chat/completions
  → 验证 agent_id/session_id/权限
  → 读取 runtime 或 session DSL
  → Canvas 构造时执行 Graph.load / Canvas.load
  → 从 Begin 节点执行
  → 变量解析和组件 invoke
  → 节点事件/SSE
  → 创建或更新 API4Conversation，保存消息、DSL、引用和错误
```

无 `session_id` 的运行会从调用者 runtime replica 加载模板、重置本轮状态，并创建 `source=workflow` 会话；已有 workflow 会话从会话自己的 DSL 恢复，普通 Agent 会话走 `canvas_service.completion()`。接口支持常规内部事件格式和 `openai-compatible` 格式。两种 wire format 不能混在同一客户端解析器中。

## 8. Session

Agent Session 使用 `API4Conversation`，字段包括：

- `dialog_id=agent_id`；
- `source=agent/workflow`；
- `message/reference`；
- `dsl`；
- `version_title`；
- `errors/duration/round`。

继续 Session 时，路由会验证 Session 确实属于请求中的 Agent，并再次验证 Canvas 可访问性。

## 9. 单组件 Debug

```text
GET input-form
  → Canvas 根据 DSL 找到组件
  → 返回该组件所需输入

POST debug(params)
  → Canvas.reset
  → component.reset
  → 注入调试输入
  → component.invoke
  → 消费同步/异步生成器
  → 返回 outputs
```

它适合验证单节点，不代表完整 Graph 的变量和分支一定正确。

## 10. 运行日志

Agent 运行日志可按 `{agent_id}-{message_id}-logs` 暂存在 Redis，由 `/logs/<message_id>` 返回。前端 Log Sheet 展示：

- 节点顺序；
- 输入输出；
- 工具名称；
- 耗时和错误；
- Workflow timeline。

Redis 清理后，这类短期日志可能消失；持久会话仍在 `API4Conversation`。

## 11. 组件类别

常见组件可按职责分组；表中列出当前 Python 可定位的类名，前端显示名称与 Go 节点名可能不同：

| 类别 | 示例职责 |
|---|---|
| 控制 | Begin、Switch、Iteration、Loop、ExitLoop、UserFillUp |
| 模型 | LLM、Agent、Categorize |
| RAG | Retrieval（可选择知识库或 Memory） |
| 工具 | Invoke、Browser、ExeSQL、Email；Agent 内绑定 MCP 工具会话 |
| 数据 | CodeExec、DataOperations、StringTransform、Parser、Tokenizer |
| 状态与输出 | VariableAssigner、VariableAggregator、Message |

每个组件最终遵守 Component 输入/输出契约，Canvas 不应为每个业务组件硬编码执行细节。

## 12. MCP、数据库与外部工具

Agent 可引用 MCP Server、数据库连接和第三方工具。调试关注：

- 连接配置属于 tenant；
- `download-dsl.ts` 调用 `clearSensitiveFields()`，按已登记的工具类型清除 `params.api_key` 和部分前端节点表单中的 API Key；
- 这不是对任意 Header、密码、环境变量的通用脱敏，导出前还需核对自定义字段；
- 超时、重试和 SSRF 防护；
- 工具输出大小与 Prompt 预算。

`/agents/test_db_connection` 只验证连接，不代表业务 SQL 已授权或安全。

## 13. 文件与附件

`/agents/<id>/upload` 将运行输入文件交给 `FileService.upload_info`。预览/下载使用 Agent attachment 路由。附件与知识库 Document 是不同生命周期，不应自动当成已解析知识库文档。

## 14. Webhook

Webhook 把外部 HTTP 请求转换成 Agent 输入：

```text
外部请求
  → /agents/<id>/webhook
  → 验证 Agent/发布配置
  → Header/Query/Body 映射
  → 执行 Canvas
  → 返回结果并记录日志
```

测试路由与正式 Webhook 分开。生产配置应限制秘密、请求体大小和可调用工具。

## 15. Dataflow 与 Agent

两者都保存在 `UserCanvas`，通过 `canvas_category` 区分：

- `agent_canvas`：对话/工作流产品；
- `dataflow_canvas`：知识库摄取流水线。

Dataflow 被知识库 `pipeline_id` 引用，并由 Task Executor 执行，不应按普通对话 Agent 理解。

### 权限、模型与取消边界

`UserCanvasService.accessible()` 允许所有者，以及属于所有者 tenant 且画布 `permission=team` 的用户访问。当前更新、调试与运行使用访问校验，删除使用 owner 校验；“能读共享画布”和“只能所有者编辑”不能直接画等号。Session 路由另查会话与 Agent 的归属。

Agent 的模型通常存于各节点的 `params.llm_id`，`LLM/Agent` 按 Canvas 的 tenant 调用 `resolve_model_type()`、`resolve_model_config()` 后绑定 `LLMBundle`；不同节点可以使用不同模型。Knowledgebase、Memory 与 Agent 的模型配置并不共享一个顶层 `llm_id`。

前端 `useStopMessage()` 调用任务取消接口，后端向 `<task_id>-cancel` 写 Redis 标记；Canvas 在检查点观察标记。断开 SSE 或收到取消响应不表示线程、远端模型或外部工具已物理停工。当前 `delete_agent()` 仅删除 `UserCanvas` 行，没有在该入口同步清理版本、会话或 Redis 副本；删除排查应分别核对这些状态。
