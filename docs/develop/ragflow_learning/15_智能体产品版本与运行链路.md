# 第十五册：智能体产品、版本与运行链路

本册补充智能体作为产品的创建、编辑、发布、会话、调试、日志与 Webhook。Canvas/DSL 执行原理参见[第四册](./04_智能体与前端.md)。

## 1. 前端页面

```text
web/src/pages/agents/          列表、模板、创建、导入、标签
web/src/pages/agent/           Canvas 编辑器与运行
web/src/pages/agent/share/     分享运行
web/src/pages/agent/log-sheet/ 节点执行时间线
web/src/pages/agent/webhook-sheet/ Webhook 日志
```

主要服务在 `web/src/services/agent-service.ts`，路由在 `web/src/routes.tsx` 的 Agent、AgentShare、AgentLogPage 等节点。

## 2. 数据模型

### `UserCanvas`

| 字段 | 作用 |
|---|---|
| `id` | Agent/Canvas ID |
| `user_id` | 所有者/tenant |
| `title/description/avatar/tags` | 产品元数据 |
| `permission` | `me|team` |
| `release` | 是否发布 |
| `canvas_type` | 模板/类型 |
| `canvas_category` | `agent_canvas|dataflow_canvas` |
| `dsl` | 节点、边、变量和组件配置 |

### 相关模型

- `CanvasTemplate`：内置/可选模板；
- `UserCanvasVersion`：DSL 历史和发布版本；
- `API4Conversation`：Agent 会话；
- `MCPServer`：远程工具服务配置；
- Redis：短期运行日志和中间状态；
- `PipelineOperationLog`：Dataflow/摄取流水线日志。

## 4. 创建 Agent

```text
模板或空白 DSL
  → POST /agents
  → 注入 user_id/canvas_category
  → normalize_dsl
  → 校验 title 唯一
  → 保存 UserCanvas
  → 创建/更新 UserCanvasVersion
  → CanvasReplicaService.replace_for_set
  → 返回 Agent
```

`CanvasReplicaService` 维护运行时可执行副本。数据库保存成功但副本同步失败时，接口会明确返回“canvas saved, but replica sync failed”，这属于部分成功状态。

## 5. 编辑和保存

前端把画布状态转换为 DSL：

```text
React Flow nodes/edges/forms
  → use-build-dsl
  → PUT /agents/<id>
  → normalize_dsl
  → Canvas.validate_component_parameters
  → UserCanvas.update
  → UserCanvasVersion.save_or_replace_latest
  → 更新 runtime replica
```

保存失败应区分：

- 表单/组件参数错误；
- DSL 图结构错误；
- MySQL 保存失败；
- runtime replica 同步失败。

## 6. 版本与发布

`UserCanvasVersion` 保存：title、description、release、dsl。当前保存逻辑会更新最新未发布版本；当最新版本已发布时，再编辑应产生新版本，避免覆盖已发布 DSL。

运行模式需要区分：

- 编辑/草稿调试：运行当前 runtime replica；
- 已发布分享：加载最新 released version；
- Session：创建时保存 version title，保证历史可追踪。

## 7. Canvas 运行

```text
POST /agents/chat/completions
  → 验证 agent_id/session_id/权限
  → 读取 runtime 或 session DSL
  → Canvas.load / Graph.load
  → 从 Begin 节点执行
  → 变量解析和组件 invoke
  → 节点事件/SSE
  → API4Conversation 保存消息、DSL、引用和错误
```

接口支持常规内部事件格式和 `openai-compatible` 格式。两种 wire format 不能混在同一客户端解析器中。

## 8. Session

Agent Session 使用 `API4Conversation`，字段包括：

- `dialog_id=agent_id`；
- `source=agent/workflow`；
- `message/reference`；
- `dsl`；
- `version_title`；
- `errors/duration/round`。

继续 Session 时，路由会验证 Session 确实属于请求中的 Agent，并再次验证 Canvas 可访问性。

## 9. 单组件 Debug

```text
GET input-form
  → Canvas 根据 DSL 找到组件
  → 返回该组件所需输入

POST debug(params)
  → Canvas.reset
  → component.reset
  → 注入调试输入
  → component.invoke
  → 消费同步/异步生成器
  → 返回 outputs
```

它适合验证单节点，不代表完整 Graph 的变量和分支一定正确。

## 10. 运行日志

Agent 运行日志可按 `{agent_id}-{message_id}-logs` 暂存在 Redis，由 `/logs/<message_id>` 返回。前端 Log Sheet 展示：

- 节点顺序；
- 输入输出；
- 工具名称；
- 耗时和错误；
- Workflow timeline。

Redis 清理后，这类短期日志可能消失；持久会话仍在 `API4Conversation`。

## 11. 组件类别

常见组件可按职责分组：

| 类别 | 示例职责 |
|---|---|
| 控制 | Begin、Answer、Switch、Iteration、Loop |
| 模型 | LLM、Classifier、Rewrite |
| RAG | Retrieval、Knowledge、Citation |
| 工具 | HTTP、SQL、Email、Search、MCP |
| 数据 | Code、Template、Parser、Tokenizer |
| 状态 | Memory、Variable、Message |

每个组件最终遵守 Component 输入/输出契约，Canvas 不应为每个业务组件硬编码执行细节。

## 12. MCP、数据库与外部工具

Agent 可引用 MCP Server、数据库连接和第三方工具。调试关注：

- 连接配置属于 tenant；
- API Key/Header 不进入导出的 DSL；
- `download-dsl.ts` 会清除敏感字段；
- 超时、重试和 SSRF 防护；
- 工具输出大小与 Prompt 预算。

`/agents/test_db_connection` 只验证连接，不代表业务 SQL 已授权或安全。

## 13. 文件与附件

`/agents/<id>/upload` 将运行输入文件交给 `FileService.upload_info`。预览/下载使用 Agent attachment 路由。附件与知识库 Document 是不同生命周期，不应自动当成已解析知识库文档。

## 14. Webhook

Webhook 把外部 HTTP 请求转换成 Agent 输入：

```text
外部请求
  → /agents/<id>/webhook
  → 验证 Agent/发布配置
  → Header/Query/Body 映射
  → 执行 Canvas
  → 返回结果并记录日志
```

测试路由与正式 Webhook 分开。生产配置应限制秘密、请求体大小和可调用工具。

## 15. Dataflow 与 Agent

两者都保存在 `UserCanvas`，通过 `canvas_category` 区分：

- `agent_canvas`：对话/工作流产品；
- `dataflow_canvas`：知识库摄取流水线。

Dataflow 被知识库 `pipeline_id` 引用，并由 Task Executor 执行，不应按普通对话 Agent 理解。

## 16. 调试入口

```bash
rg '@manager.route\("/agents' api/apps/restful_apis/agent_api.py
rg 'class Canvas|class Graph|def load|def run' agent
rg 'CanvasReplicaService|UserCanvasVersionService' api

```

关键 ID：`agent_id → version_id/session_id → message_id → component_id`。
